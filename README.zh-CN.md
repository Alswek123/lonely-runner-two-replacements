# 孤独跑者的两项速度替换

把速度表 1, 2, …, n−1 中的两项换成两个不同的整数 u 和 w，其中 n ≤ u < w。跑道周长为 1，所有人从原点出发。如果在最有利的时刻，离原点最近的跑者也恰好只离原点 1/n，就称这张速度表为紧配置。

[证明草稿（PDF）](runner.pdf) · [LaTeX 源码](runner.tex) · [English](README.md)

## 结论

证明草稿给出 u = O(n log log n) 和 w = O(n log n)。它们对任意两项替换成立，只要求所得配置是紧的。较小速度的量级可以达到。草稿给出了无穷多个 n，使 u 与 n log log n 的比值趋近于 1/2。较大速度的最优增长量级仍待确定。

Yuhan Zhang 在第 8.2 问询问多项替换的速度界。这里处理恰好两项。较小速度的下界使用了 Goddyn 与 Wong 在 2006 年发表的同时加速构造。第 4 节选择参数并计算其增长率，第 5 节用若干有理时刻建立较大速度的上界。草稿由 OpenAI Codex 完成，尚待独立数学审阅。

- [Zhang 的第 8 节及原问题](https://arxiv.org/html/2608.13599v3#S8)
- [Goddyn 与 Wong 原文的期刊存档](https://zenodo.org/records/8275490)

## 如何复核

1. 阅读 `runner.pdf`。一般上界的推导在第 2 至 5 节，计算方法在第 6 节。`runner.tex` 是排版源文件。
2. 用 Python 3 在仓库根目录运行 `python crosscheck.py`。这个程序使用标准库的任意精度有理数，对 n = 8 至 18 从头穷举，并在原始不等式上逐个检查三个最终例子。
3. 用 C++17 编译器编译 `census.cpp`，例如 `g++ -O3 -std=c++17 census.cpp -o census`。运行 `./census 8 300` 可重算完整范围；在 Windows PowerShell 中使用 `.\census.exe 8 300`。两个参数是起止值，均包含在内。可以先运行 `./census 70 75` 核对 n = 74 的例子。
4. 若要将重算结果逐行与随附数据比较，运行 `python replay.py ./census 8 300`，Windows 上运行 `python replay.py .\census.exe 8 300`。

## 数据

`tight_sets.csv` 中每行依次为 n、被删的两个速度和新加入的两个速度。`census_by_n.csv` 每行对应一个 n，记录进入循环的 u 和 (u,w) 候选数、各删除对中最大的 u 搜索上限、实际进入 w 循环时最大的 w 上限，以及最终紧配置数。同一个新速度用于不同删除对时单独计数。即使搜索上限低于 n，也参与 u 上限的汇总。

完整范围共有 4,455,065 种删除对，最终在 n = 8、74、284 各留下一个例子。每个例子在 t = 1/n 达到等号。有限计算使用区间端点的整数比较，实际搜索范围由证明逐个给出，事先无需规定新速度上限。计算结果与一般上界的证明可以独立审阅。
